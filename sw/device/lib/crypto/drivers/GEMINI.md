# OpenTitan Crypto Drivers Context

You are assisting in the development of low-level hardware drivers for the OpenTitan Cryptographic Library. This layer interfaces directly with hardware IP via MMIO.

## 1. MMIO & Register Access
- **Base Addresses:** Always define a local `kBase` constant using the autogenerated top-level headers (e.g., `TOP_EARLGREY_AES_BASE_ADDR`).
- **Shadowed Registers:** Use `abs_mmio_write32_shadowed` for registers that require shadowed writes to prevent configuration corruption.
- **Spin Loops:** Use the `spin_until` pattern to poll hardware status bits. Always check for FATAL or RECOVERABLE alert bits within these loops to avoid infinite hangs during hardware failure.

## 2. Security & Hardening (Critical)
- **Fault Injection (FI) Resistance:** 
    - Use `launder32()` in switch statements and critical loop counters to prevent the compiler from optimizing out security-critical checks.
    - After writing a configuration to hardware, **read it back** and compare it against the expected value using `HARDENED_CHECK_EQ`.
- **Side-Channel Defense:** 
    - Use `hardened_memshred` to clear hardware key registers before and after use.
    - When writing multi-share keys, separate the writes (e.g., write Share 0, then Share 1) to avoid leaking the full key through the ALU or bus simultaneously.
- **Integrity:** Implement `_integrity_checksum` functions for all key structures using `crc32`.

## 3. Coding Style & Macros
- **Module ID:** Every driver must define a unique `MODULE_ID` using `MAKE_MODULE_ID('d', 'x', 'y')`. For example, AES uses `dae`.
- **Status Codes:** Functions must return `status_t`. Use `OTCRYPTO_OK`, `OTCRYPTO_BAD_ARGS`, or `OTCRYPTO_RECOV_ERR`.
- **Booleans:** Never use standard `bool`. Always use `hardened_bool_t` (`kHardenedBoolTrue` / `kHardenedBoolFalse`).

## 4. Build System (Bazel)
- **Adding a Driver:** Add a `cc_library` in the `BUILD` file. 
- **Dependencies:** 
    - Always include `//sw/device/lib/base:abs_mmio` and `//sw/device/lib/base:hardened`.
    - Reference autogenerated register headers via `//hw/ip/[module]/data:[module]_c_regs`.
- **Testing:** Every driver must have a corresponding `opentitan_test` rule using `CRYPTO_EXEC_ENVS`.
